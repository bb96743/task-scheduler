# 演示操作步骤（逐步照做版）

> 一条 3 分钟视频，四个场景：**注册任务 → 立即执行/分片 → 失败重试 → 告警通知**。
> 本文按「点哪里 → 看到什么 → 说什么」写，每一步都能独立核对。
> 配套文档：`docs/录屏脚本.md`（旁白逐字稿）、`docs/验收对照.md`（平台 11 条对照）。

---

## 零、开录前 3 分钟（不进画面）

### 0.1 重置成干净数据

```bash
cd D:/jianli/task-scheduler/backend
# 停掉正在跑的服务（Ctrl+C 或 kill 掉 java 进程）
rm -rf data
java -jar target/task-scheduler-1.0.0.jar --spring.profiles.active=demo --server.port=8080
```

看到这行就算好了：

```
Started SchedulerApplication in x.xxx seconds
```

一定要 `rm -rf data`：不删的话上次的 `verify-task`、几十条执行记录、旧告警都还在，
画面会显得乱，而且「注册任务」这一步可能因为重名失败。

### 0.2 核对起点数据（30 秒）

浏览器开 `http://localhost:8080`，确认三件事：

| 位置 | 应该是 |
|------|--------|
| 顶部统计 | 任务总数 **5**、启用中 **4**、告警记录 **0** |
| 任务列表 | 5 行：`demo-success-task` / `demo-fail-task` / `demo-shard-task` / `demo-flaky-task` / `demo-paused-task`（停用） |
| 右上角 | `在线节点 1/1` |

对不上就重来一次——多半是没删 `data` 目录。

### 0.3 浏览器与桌面

- 窗口 **1440×900 或更大**，缩放 100%（别用 125%，表格会挤）。
- 只留一个标签页 `http://localhost:8080`；Swagger 先别开，收尾再开。
- 关掉书签栏（Ctrl+Shift+B）、关掉微信/QQ/钉钉通知。

### 0.4 时间对齐（决定成片质量的一步）

`demo-fail-task` 的 cron 是 `0/60 * * * * ?`，**每分钟 :00 触发**：
`:00` 首次失败 → 约 `:05` 第一次重试 → 约 `:15` 第二次重试 → 随即落告警。

所以：**在每分钟的 :35～:45 之间按下录制键**。
这样开场讲统计卡时正赶上一次失败链在后台跑完，讲到「失败重试」（约 1 分 25 秒处）时，
抽屉里已经躺着一条完整的三段链路，不用干等。

> 判断方法：开录前看一眼系统时钟，秒数在 35–45 之间就按录制。

## 一、分步操作（时间轴按录制起点 t=0）

### STEP 1 — t=0:00 首页概览（15 秒）

**操作**
1. 鼠标从左上角标题「分布式任务调度中心」开始。
2. 沿顶部统计卡从左到右缓慢划一遍，每张停 1 秒：
   `任务总数 → 启用中 → 执行成功 → 执行失败 → 告警记录`。
3. 划到右上角 `在线节点 1/1` 的绿色标签上停一下。

**看到什么**：5 张卡，数字是实时统计（每 5 秒自动刷新）。

**说什么**
> 「这是分布式任务调度中心的管理台。5 个预置示例任务已经在跑，上面是实时统计。
> 整个系统只用了一个数据库——没有 Redis、没有 ZooKeeper，去重靠数据库唯一约束。」

---

### STEP 2 — t=0:15 打开注册弹窗

**操作**
1. 点右上角蓝色按钮 **「注册任务」**。
2. 弹窗标题「注册任务」，光标默认在「任务名」输入框。

**看到什么**：一个 560px 宽的弹窗，8 个字段：
`任务名 / 分组 / cron 表达式 / 处理器 / 分片数 / 最大重试 / 重试间隔(秒) / 备注`。

**说什么**
> 「注册一个任务，只需要填 cron、处理器、分片数、重试策略这几样。」

---

### STEP 3 — t=0:22 填表单（重点：cron 与处理器）

按顺序填，**其余保持默认**：

| 字段 | 填什么 | 说明 |
|------|--------|------|
| 任务名 | `verify-task` | 演示用名字 |
| 分组 | `VERIFY` | 覆盖默认值 `DEFAULT` |
| cron 表达式 | `0 0/5 * * * ?` | **推荐**：每 5 分钟触发，录制期间不会自己跑，画面最干净 |
| 处理器 | 下拉选 **`demoShardHandler（分片）`** | 关键，4 分片并行的前提 |
| 分片数 | `4` | 点数字框右侧 `+` 三次 |
| 最大重试 | `2` | |
| 重试间隔(秒) | `5` | |
| 备注 | `录屏演示：4 分片并行` | |

> ⚠️ 别用 `0/30 * * * * ?`：那会每 30 秒自动触发，抽屉里混进 CRON 记录，
> 「立即执行」那一步的画面就不干净了。想演示「定时 + 手动并存」时才用它。

**说什么**（填 cron 时顺口带一句）
> 「cron 是 Quartz 六段式，保存时服务端会立即解析校验，写错了直接报错、不会存进来。
> 保存后系统会马上算出下次触发时间。这里我配成每 5 分钟，避免演示时它自己插进来。」

---

### STEP 4 — t=0:40 提交，观察列表

**操作**
1. 点弹窗右下角 **「确定」**。
2. 弹窗关闭，列表最下面出现新行 `verify-task`。
3. 鼠标指向这一行的 **「下次触发」** 列。

**看到什么**
- 状态标签：绿色 **`启用`**
- 分片 `4`、重试 `2`
- 下次触发：一个具体的未来时刻（如 `19:05:00`）
- 顶部「任务总数」由 5 变成 **6**

**说什么**
> 「保存之后立刻生效，下次触发时间已经算好了，任务总数也从 5 变成 6。」

> 兜底：若报「任务名已存在」，说明 `data` 没删干净 —— 把任务名改成 `verify-task-2` 继续录，别卡在这里。

---

### STEP 5 — t=0:50 立即执行

**操作**
1. 在 `verify-task` 行的操作列点 **「立即执行」**。
2. 右侧抽屉滑出，标题 **「执行记录 · verify-task」**。
3. **等 5 秒**（页面 5 秒自动刷新一轮，不用手点刷新）。

**看到什么**

| 列 | 值 |
|----|----|
| 触发 | `MANUAL` |
| 节点 | `node-1` |
| 状态 | 先 `RUNNING`（蓝）→ 5 秒内变 `SUCCESS`（绿） |
| 分片(成/败) | `4/0` |
| 耗时 | 约 `1000–1700 ms` |

**说什么**
> 「点立即执行，生成一条手动触发的执行记录。注意节点这一列——执行记录是记在具体节点上的。」

---

### STEP 6 — t=1:00 看分片并行

**操作**
1. 鼠标指向 `4/0` 那一格，停 1 秒。
2. 指向「耗时」列，停 1 秒。
3. 点该行 **「分片」** 按钮。

**看到什么**：弹窗「分片明细 · #ID」，4 行：

| 分片 | 状态 | 耗时 | 结果摘要 |
|------|------|------|----------|
| 0 | SUCCESS | ~815 ms | 处理 250 条… |
| 1 | SUCCESS | ~819 ms | 处理 250 条… |
| 2 | SUCCESS | ~817 ms | 处理 250 ms… |
| 3 | SUCCESS | ~815 ms | 处理 250 条… |

**关键对比点（强烈建议说出来）**：4 个分片各 800 毫秒左右，总耗时也才 1 秒多 —— 是**并行**的；
串行执行要 3.2 秒以上。

**说什么**
> 「4 个分片是并行跑的，每个分片 800 毫秒左右，总耗时 1 秒多。
> 如果是串行，这里要 3 秒以上。分片粒度的状态、耗时、结果摘要都能查到。」

关闭弹窗（右上角 ×）。

---

### STEP 7 — t=1:12 看日志

**操作**
1. 点同一行 **「日志」**。
2. 弹窗「执行日志 · #ID」，默认「全部」级别。
3. 停 2 秒，让镜头看清 `INFO` 级别、`分片` 列从 0 到 3 各两条。
4. 点一下顶部 **`ERROR`** 单选，画面变空（这次执行没有错误日志）。
5. 关闭弹窗。

**看到什么**：8 条 INFO 日志（4 个分片 × 开始/完成各一条）；切 ERROR 后为空。

**说什么**
> 「日志是按分片采集的，能按 INFO/ERROR 过滤。这次全成功，所以 ERROR 下面是空的。」

关闭执行记录抽屉（右上角 ×）。

---

### STEP 8 — t=1:25 进入失败重试链

**操作**
1. 在任务列表找到 **`demo-fail-task`** 这一行（它的「状态」是启用，重试列 `2`）。
2. 点操作列 **「更多」** → 下拉里选 **「执行记录」**。
3. 抽屉标题变成「执行记录 · demo-fail-task」，**从上往下**就是重试链。

**看到什么**（新的在上，所以顺序是倒的：RETRY#2 → RETRY#1 → CRON）

| 触发 | 节点 | 状态 | 说明 |
|------|------|------|------|
| `RETRY#2` | node-1 | FAILED | 第二次重试，距首次约 15 秒 |
| `RETRY#1` | node-1 | FAILED | 第一次重试，距首次约 5–7 秒 |
| `CRON` | node-1 | FAILED | :00 定时首次触发 |

**说什么**
> 「这是失败重试。任务配了重试 2 次、间隔 5 秒。实际间隔是指数退避——第一次 5 秒，第二次 10 秒。
> 重试次数记在执行记录上，所以能看出完整链路：CRON、RETRY#1、RETRY#2，三次都是失败。」

---

### STEP 9 — t=1:45 指引数退避与终态

**操作**
1. 鼠标依次点这四行的 **「触发时刻」** 列，让观众看到时间差（`19:00:00` / `19:00:07` / `19:00:17` 这类）。
2. 用手势或鼠标点住最上面那条 `RETRY#2`，说明「这是最后一次重试」。

**说什么**
> 「时间戳能看出退避：5 秒、10 秒，不是固定间隔反复重试。
> 重试耗尽才转终态失败，也才触发告警——中间重试过程不会误报。」

> 兜底：若抽屉里只有一条 `CRON`，说明重试还没跑完（`:00` 触发后要 ~17 秒）。
> 别停在这里等，先讲这一段，讲到告警再回来看——或者干脆这轮录完重录，开录时间提前到 :20。

---

### STEP 10 — t=2:00 手工补偿（可选，时间紧可跳过）

**操作**
1. 在任意一条 `FAILED` 行点 **「补偿」**。
2. 抽屉自动刷新，最上面多出一条 `COMPENSATE` 记录。
3. 鼠标指向这条记录的 **「触发」** 列。

**看到什么**：新增一行 `COMPENSATE`，状态 `SUCCESS`（或再次 `FAILED`），
并且能在列表里和原失败记录对照。

**说什么**
> 「失败终态可以手工补偿，系统会生成一条新的执行记录并标注补偿来源，不会去改原来的失败记录。」

> 注意：补偿也是走同一个失败处理器，大概率再失败一次 —— 这是**正常**的，
> 说明补偿是「重新跑一次」而不是「假装成功」。

---

### STEP 11 — t=2:20 告警记录

**操作**
1. 关闭抽屉。
2. 点顶部 **「告警记录 (N)」** 标签。
3. 鼠标指向最新一条记录，从左到右划一遍：`任务 → 连续失败 → 通道 → 内容 → 时间`。

**看到什么**：一条 `demo-fail-task` 的告警，内容形如
`任务 [demo-fail-task] 连续失败 5 次，已触发告警（阈值 2）`，通道 `LOG`。

> 口播别死记「5 次」——跑得越久数字越大。说「连续失败达到阈值」即可。

**说什么**
> 「连续失败达到阈值就落一条告警。注意这里只有 **一条**，不是每失败一次报一次——
> 5 分钟内同一任务只报一次，避免刷屏。并发场景下还有唯一键兜底，保证不会重复落库。」

---

### STEP 12 — t=2:35 告警配置（可选）

**操作**
1. 切回 **「任务列表」** 标签。
2. `demo-fail-task` 行 → **「更多」** → **「分片/告警配置」**。
3. 弹窗标题「任务配置」，下半部分是「告警配置」分割线。

**看到什么**：`分片数 1` / `连续失败阈值 2` / `通知通道 LOG` / `启用告警 开`。

**说什么**
> 「阈值和通知通道是按任务配的，不是全局一刀切。」

点「取消」关闭。

---

### STEP 13 — t=2:50 收尾：节点 + OpenAPI

**操作**
1. 点顶部 **「节点」** 标签，停 2 秒。
2. 地址栏把 `http://localhost:8080` 改成 `http://localhost:8080/swagger-ui.html` 回车
   （会自动跳到 `/swagger-ui/index.html`，属正常）。
3. 等分组展开，鼠标从上往下划过接口列表，停 2 秒。

**看到什么**
- 节点页：`node-1 / 127.0.0.1 / ONLINE / 最后心跳`（心跳每 5 秒更新）+ 一行说明文字。
- Swagger：14 个路径、16 个方法。

**说什么**
> 「节点心跳在这里，双节点部署时两个节点都会出现，同一任务同一时刻只在一个节点执行——
> 双节点实测记录在仓库 docs 目录。16 个接口的 OpenAPI 文档也是自带的。」

**结束录制**。

## 三、翻车兜底表

| 现象 | 原因 | 处理 |
|------|------|------|
| 「注册任务」报任务名已存在 | `data` 目录没删 | 换名 `verify-task-2` 继续，或重来 |
| 抽屉里只有 CRON，没有 RETRY | 重试还没跑到 | 等到下一次整分；或先讲别的再回来 |
| 状态一直 RUNNING | 还没到刷新周期 | 等 5 秒；分片任务一般 1 秒内完成 |
| 告警记录是 0 条 | 失败链没走完，或还没到 :15 | 等到下一个整分 :20 之后 |
| 「立即执行」是灰的 | 该任务被停用了 | 只有 `demo-paused-task` 会这样，换个任务 |
| 分片弹窗空白 | 该任务分片数为 1 | 只能用 `demo-shard-task` / `verify-task` |
| 表格出现横向滚动条 | 浏览器缩放 > 100% | 调回 100% |
| 中文显示成方块 | 内核不对 | 用 Chrome / Edge |
| 端口 8080 被占用 | 旧进程没退 | `netstat -ano \| findstr 8080` 找到 PID 后 `taskkill /PID <pid> /F` |

## 四、时间不够时的裁剪顺序

只能录 2 分钟时，按这个顺序砍：

1. 砍 **STEP 12**（告警配置弹窗）—— 口播一句带过即可。
2. 砍 **STEP 10**（补偿）—— 只口播「失败终态可补偿」。
3. 砍 **STEP 7** 的 ERROR 过滤 —— 只展示全部日志。
4. **不要砍** STEP 3–6（注册 + 分片）和 STEP 8（重试链），这是四个必考场景里的两个。
