# 3 分钟录屏脚本（照着做即可）

> 目标：一条 3 分钟视频，覆盖**注册任务 → 立即执行 → 模拟失败重试 → 告警通知**四个场景。
> 环境：本机 `demo` profile，H2 内存库，无需 MySQL/Redis。

## 一、录屏前 2 分钟准备

**1. 重启一个干净的演示环境**（每次重启数据都是全新的 5 个示例任务）

```bash
cd D:/jianli/task-scheduler/backend
rm -rf data
java -jar target/task-scheduler-1.0.0.jar --spring.profiles.active=demo --server.port=8080
```

看到 `Started SchedulerApplication` 后，浏览器打开 `http://localhost:8080`。

**2. 浏览器窗口设为 1440×900 或更大**，关掉无关标签页、书签栏、通知弹窗。

**3. 时间对齐（让失败重试发生在镜头里）**

`demo-fail-task` 是**每分钟整点触发**：`:00` 触发 → 约 `:05` 第一次重试 → 约 `:15` 第二次重试 → 随即触发告警。

建议在**每分鐘的 :35–:45 之间按下录制键**，这样讲到「失败重试」时（约 1 分 25 秒处）正好能看到一条新鲜的完整链路。

**4. 桌面清干净**，任务栏收起，别露出微信/QQ 弹窗。

---

## 二、分段脚本

### 0:00–0:15 开场（15 秒）

**画面**：管理台首页，鼠标缓慢划过顶部 5 个统计卡（任务总数 / 启用中 / 执行成功 / 执行失败 / 告警数）。

**旁白**：
> 「这是分布式任务调度中心的管理台。5 个预置示例任务已经跑起来了，上面是实时统计。整个系统只用了一个数据库，没有 Redis、没有 ZooKeeper。」

---

### 0:15–0:50 场景一：注册任务（35 秒）

**操作**：
1. 点右上角「注册任务」
2. 按下表填写（其余保持默认）：

| 字段 | 填什么 |
|------|--------|
| 任务名 | `verify-task` |
| 分组 | `VERIFY` |
| cron 表达式 | `0/30 * * * * ?` |
| 处理器 | 下拉选 `demoShardHandler（分片）` |
| 分片数 | `4` |
| 最大重试 | `2` |
| 重试间隔(秒) | `5` |
| 备注 | `录屏演示：4 分片并行` |

3. 点「确定」，列表出现 `verify-task`，状态「启用」，下次触发时间已算出。

**旁白**：
> 「注册一个任务只要填 cron、处理器、分片数和重试策略。cron 会在保存时立即校验，非法表达式直接报错。保存后系统立刻算出下次触发时间。」

---

### 0:50–1:25 场景二：立即执行 + 分片并行（35 秒）

**操作**：
1. 在 `verify-task` 行点「立即执行」
2. 右侧抽屉弹出，第一条记录 `MANUAL / RUNNING`；**等 5 秒**，自动刷新成 `SUCCESS`
3. 鼠标指向这一行的「分片(成/败)」列，显示 `4/0`；指向「耗时」列，显示约 `800 ms`
4. 点该行「日志」，弹出 8 条日志（4 个分片各 2 条），停 2 秒后关闭
5. 点该行「分片」，弹出 4 条分片明细，每条有状态、耗时、结果摘要；关闭

**旁白**：
> 「点立即执行，系统生成一条手动触发的执行记录。4 个分片是并行跑的，总耗时 800 毫秒左右——如果串行要 3 秒多。分片粒度的状态、耗时、结果摘要都能查到。」

---

### 1:25–2:20 场景三：模拟失败重试（55 秒）

**操作**：
1. 关掉抽屉，在任务列表找到 `demo-fail-task`（就是刚才告警的那个），点「更多 → 执行记录」
2. 抽屉里从上往下就是重试链，鼠标依次指这四条：

| 触发 | retryCount | 状态 | 含义 |
|------|-----------|------|------|
| `CRON` | 0 | FAILED | 首次触发失败 |
| `RETRY` | 1 | FAILED | 5 秒后第 1 次重试 |
| `RETRY` | 2 | FAILED | 10 秒后第 2 次重试 |
| — | — | — | 超过上限，转终态失败 |

3. （可选，若时间够）点其中一条 FAILED 的「补偿」，抽屉顶部多出一条 `COMPENSATE` 记录，并把「补偿来源」指给镜头看

**旁白**：
> 「这是失败重试。任务配了重试 2 次、间隔 5 秒，实际间隔是指数退避——第一次 5 秒，第二次 10 秒。重试次数是记在执行记录上的，所以能看出完整链路。重试耗尽才转终态失败，也才触发告警，中间过程不会误报。失败终态可以手工补偿，系统会生成一条新执行并记录补偿来源。」

---

### 2:20–2:50 场景四：告警通知（30 秒）

**操作**：
1. 关掉抽屉，切到顶部「告警记录」标签
2. 指着最新一条：`任务 [demo-fail-task] 连续失败 N 次，已触发告警（阈值 2）`，右侧有时间
   （刚重启的环境第一次出现时 N 是 3，跑得越久 N 越大，念「连续失败达到阈值」即可，别念具体数字）
3. 切回「任务列表」，在 `demo-fail-task` 行点「更多 → 分片/告警配置」，弹出阈值与通道配置

**旁白**：
> 「连续失败达到阈值就落一条告警记录，5 分钟内同一任务只报一次，避免刷屏。阈值和通知通道是按任务配的，这里可以改。」

---

### 2:50–3:00 收尾（10 秒）

**操作**：切到顶部「节点」标签，停 2 秒；再打开 `http://localhost:8080/swagger-ui.html`，露出 16 个接口的列表。

**旁白**：
> 「节点心跳、16 个接口的 OpenAPI 文档都在这里。双节点部署下同一任务同一时刻只在一个节点执行，实测记录在仓库 docs 目录。」

---

## 三、常见问题

| 现象 | 处理 |
|------|------|
| 执行记录抽屉是空的 | 该任务还没跑过，等 30 秒或直接点「立即执行」 |
| 状态一直 `RUNNING` | 页面 5 秒自动刷新，等一轮即可；分片任务约 1 秒完成 |
| 告警记录没有 | `demo-fail-task` 每分钟 :00 触发，:15 前必出；等一个整分钟 |
| 分片弹窗空白 | 只对分片数 > 1 的任务有数据，`verify-task` 是 4 分片，没问题 |
| 中文显示成方块 | 换用 Chrome/Edge，别用 IE 内核浏览器 |
